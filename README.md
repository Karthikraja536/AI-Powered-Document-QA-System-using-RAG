# 🤖 Document Q&A System

A Retrieval-Augmented Generation (RAG) app that lets you upload a PDF, DOCX, or TXT file and ask questions about it in plain language. Answers are generated **only** from the document's own content using Groq's `llama-3.3-70b-versatile`, HuggingFace sentence embeddings, and an in-memory FAISS vector store.

---

## Features

- Upload **PDF, DOCX, DOC\*, or TXT** files
- Semantic search over document chunks using FAISS
- Answers generated by **Groq (llama-3.3-70b-versatile)**, grounded strictly in retrieved chunks — the model is instructed to say so if the answer isn't in the document
- Streamlit chat interface with conversation history for the current session
- API key kept out of source control via `.env` (excluded by `.gitignore`)

\* Legacy `.doc` support uses `docx2txt`, which is built for the `.docx` format — see [Known Limitations](#known-limitations).

## Tech Stack

| Component | Technology |
|-----------|-----------|
| UI | Streamlit |

## Project Structure

```
Document Q&A System/
├── app.py              # Streamlit UI + file text extraction (PDF/DOCX/TXT)
├── rag_pipeline.py     # Core RAG logic: chunking, embeddings, retrieval, LLM chain
├── .env                # Your local Groq API key (not committed)
├── .gitignore
├── requirements.txt
└── README.md
```

This is a small two-file app, not a `src/`-style package — all retrieval logic is in `rag_pipeline.py`, and the UI plus text extraction is in `app.py`. There's no separate config module or test suite yet.

## Setup & Run

### 1. Clone the repository
```bash
git clone https://github.com/your-username/ai-powered-doc-qa-rag.git
cd "Document Q&A System"
```

### 2. Create and activate a virtual environment
```bash
python -m venv venv

# Windows
venv\Scripts\activate

# Mac/Linux
source venv/bin/activate
```

### 3. Install dependencies
```bash
pip install -r requirements.txt
```

### 4. Set up your environment variables
Create a `.env` file in the project root:
```
GROQ_API_KEY=your_groq_api_key_here
```
Get a free API key at: https://console.groq.com/keys

### 5. Run the app
```bash
streamlit run app.py
```

The app opens at **http://localhost:8501**

## Configuration

These values are currently hardcoded in `rag_pipeline.py` (no separate config file yet):

| Setting | Value | Location |
|---------|-------|----------|
| LLM model | `llama-3.3-70b-versatile` | `RAGPipeline.__init__` |
| Embedding model | `all-MiniLM-L6-v2` | `RAGPipeline.__init__` |
| Chunk size | `600` chars | `RAGPipeline.ingest` |
| Chunk overlap | `80` chars | `RAGPipeline.ingest` |
| Retrieved chunks (top-k) | `4` | `RAGPipeline.ingest` |
| Max response tokens | `500` | `RAGPipeline.__init__` |
| LLM temperature | `0` | `RAGPipeline.__init__` |

## How It Works

```
User uploads document
        │
        ▼
Extract raw text (PDF / DOCX / TXT)        — app.py
        │
        ▼
Split into overlapping chunks              — RecursiveCharacterTextSplitter
        │
        ▼
Embed chunks → store in FAISS vector store — HuggingFace embeddings
        │
        ▼
User asks a question
        │
        ▼
Retrieve top-4 relevant chunks             — FAISS similarity search
        │
        ▼
Groq LLM generates answer from context     — strict context-only prompt
        │
        ▼
Display answer in chat UI
```

## Known Limitations

- **In-memory vector store** — FAISS data lives in RAM only. Restarting the app clears it, so you'll need to re-upload your document each session.
- **No persistent chat history** — closing the browser tab or restarting the app clears the conversation.
- **No automated tests** — there's no `pytest` suite yet.
- **Hardcoded settings** — model name, chunk size, top-k, etc. live directly in `rag_pipeline.py` rather than a central config file.
- **`.doc` support is best-effort** — `docx2txt` is designed for the `.docx` (zip-based) format, so legacy binary `.doc` files may not extract cleanly.

## Notes

- The app answers **only from the uploaded document** — it's instructed not to use outside knowledge.
- If you see noisy startup logs from the embedding model, add this to your `.env` to quiet them:
  ```
  TRANSFORMERS_VERBOSITY=error
  ```
